# AI开发高手必修课 从入门到进阶生产级AI项目实战

获课：jzit.top/26820/

**一、课程定位：从 "能跑通" 到 "能长期跑"**

AI 开发领域最普遍的现象是：demo 几小时就能做出来，上线三个月还在修。这门必修课真正的分水岭不在于教会更多模型技巧，而在于把 "个人可运行的原型" 升级为 "团队可维护的系统"。因此课程以功能为主线：先厘清一个生产级 AI 项目必须具备哪些能力，再说明每项能力如何搭建、如何验证，最后说明这些能力如何组合成完整系统。

**二、输入与理解功能：把用户的话变成可处理的任务**

第一组功能解决 "听懂" 的问题。这里既包含原始信息的清洗与结构化，也包含提示词的角色、约束、输出格式设计，还包含上下文长度的取舍策略。课程要讲清一个判断标准：模型给出稳定、可解析结果的前提，在于输入被约束到足够明确的范围；单纯把模型调得更强并不够。同一提示词在不同长度、不同噪声的输入下表现差异巨大，因此提示词需要像接口契约一样版本化管理。

**三、知识接入功能：让模型回答 "它没学过的东西"**

企业场景里，模型不知道公司制度、产品参数、历史工单。检索增强的核心功能是 "先查到再回答"：文档解析、切分粒度、向量化、召回、重排、拼接进上下文。课程重点在于讲清失败模式：切分过粗导致召回噪声，过细则语义断裂；只做向量召回会漏掉关键词精确匹配；不做重排则前几条被无关内容挤掉。这些环节的取舍会决定最终答案的质量，因此必须建立可量化的评估。

**四、工具调用与外部执行功能：从 "会说" 到 "会做"**

模型本身不查库、不发请求、不改数据。工具调用把这层能力补齐：把业务系统封装成清晰可调用的接口，并处理参数校验、超时、幂等、失败回退。课程要强调 "模型只负责决策，系统负责兜底" 这条边界：写操作必须有确认与权限控制，异常必须能被捕获并降级为安全路径，不能让一次幻觉变成一次真实事故。

**五、流程编排功能：把单点能力串成业务闭环**

真实任务往往是多步骤的：检索、判断、调用、生成、校验。编排功能负责状态管理、分支、重试、人工介入节点以及多角色协作。课程的重点在于辨别 "该不该让模型自主规划"：流程确定的部分用固定编排更稳定、更便宜；只有开放式环节才交给模型决策。多数线上事故来自过度自主。

**六、评估与观测功能：让效果可见、可比较、可回归**

这是入门与进阶最明显的分界。功能上需要三件事：有一套贴近真实分布的测试集，有可重复的自动打分或人工标注流程，有线上埋点与追踪记录。课堂要反复训练的是一种思维方式：任何改动（换模型、改提示词、调召回）都必须先跑回归再上线；线上答案必须能追溯到当时的输入、召回内容与版本，否则问题无法定位。

**七、成本、安全与合规功能**

生产系统的三个硬约束。成本上要讲清 token 消耗结构、缓存与分级路由、批处理与小模型替代的边界；安全上要覆盖提示词注入、越权访问、敏感信息外泄、输出内容过滤；合规上要处理数据留存、脱敏与审计。这些内容是工程和产品必须具备的能力，并不属于 "加分项"。

**八、部署与演进功能**

最后落到 "怎么活下去"：从原型到灰度到全量的推进节奏、模型与提示词的版本管理、依赖降级方案、监控告警与容量规划。课程交付的不是一套代码，而是一套判断框架：这个项目现在缺哪项功能？补上之后如何证明它有效？出了问题能否在十分钟内定位？
